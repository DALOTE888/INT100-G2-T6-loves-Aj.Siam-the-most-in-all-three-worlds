# Prototype Testing: BuriromRepair

## 1. วัตถุประสงค์การทดสอบ (Objective of Testing)

ตรวจสอบว่าผู้ใช้สามารถเข้าใจและใช้งานฟีเจอร์หลักของ Prototype ได้จริง ได้แก่

- ระบบเข้าสู่ระบบสำหรับผู้ใช้งาน
- ระบบแสดงแผนที่สวนธนบุรีรมย์และตำแหน่งสิ่งอำนวยความสะดวก
- ระบบแสดงสถานะของสิ่งอำนวยความสะดวก เช่น พร้อมใช้งาน และกำลังซ่อมแซม
- ระบบแสดงรายละเอียดของแต่ละจุดผ่านการกดหมุดบนแผนที่
- ระบบแจ้งซ่อมสิ่งอำนวยความสะดวกที่เกิดความเสียหาย
- ระบบติดตามสถานะการแจ้งซ่อม
- ระบบสำหรับเจ้าหน้าที่ในการรับเรื่องและจัดการปัญหา

รวมถึงเก็บ Feedback จากผู้ใช้งาน เพื่อนำไปวิเคราะห์ปัญหาและปรับปรุง Prototype ในรอบถัดไป

## Task ที่ให้ผู้ทดสอบทำ

1. เปิดแอปพลิเคชันครั้งแรก และทดลองเข้าสู่ระบบในฐานะผู้ใช้งาน
2. สำรวจหน้าแผนที่สวนธนบุรีรมย์ และตรวจสอบว่ามีสิ่งอำนวยความสะดวกทั้งหมดกี่จุด
3. ทดลองกดหมุดบนแผนที่ เพื่อดูรายละเอียดของสิ่งอำนวยความสะดวกแต่ละจุด
4. ตรวจสอบสถานะของสิ่งอำนวยความสะดวกว่าจุดใดพร้อมใช้งาน และจุดใดกำลังซ่อมแซม
5. ทดลองค้นหาจุดที่กำลังซ่อมแซมจากแผนที่
6. ทดลองใช้งานระบบแจ้งซ่อม และเลือกประเภทปัญหาที่ต้องการแจ้ง
7. ทดลองตรวจสอบสถานะของรายการแจ้งซ่อม
8. สรุปว่าหน้าจอใดเข้าใจง่ายหรือยากที่สุด และเพราะอะไร

## คำถามหลังทดสอบ (Post-test Interview)

- ฟีเจอร์ใดใช้งานง่ายที่สุด และฟีเจอร์ใดใช้งานยากที่สุด เพราะอะไร?
- คุณเข้าใจสัญลักษณ์และสีที่ใช้แสดงสถานะบนแผนที่หรือไม่?
- การแสดงตำแหน่งสิ่งอำนวยความสะดวกบนแผนที่ช่วยให้ค้นหาสถานที่ได้ง่ายขึ้นหรือไม่?
- คุณเข้าใจความแตกต่างระหว่างสถานะพร้อมใช้งานและกำลังซ่อมแซมหรือไม่?
- คุณคิดว่ารายละเอียดของแต่ละจุดมีข้อมูลเพียงพอหรือไม่?
- หากพบสิ่งอำนวยความสะดวกชำรุดภายในสวน คุณจะเลือกใช้แอปนี้แจ้งซ่อมหรือไม่ เพราะอะไร?
- คุณต้องการให้เพิ่มฟีเจอร์อะไรในแอปพลิเคชันนี้?

# 3. What to Do Next from Test Feedback

จาก Feedback ที่ได้รับ สามารถแบ่งประเด็นที่ควรปรับปรุงออกเป็น 5 ด้าน ดังนี้

## 1. ปรับปรุงการแสดงผลแผนที่

ผู้ใช้บางคนอาจไม่เข้าใจสัญลักษณ์และสีที่ใช้แสดงสถานะของสิ่งอำนวยความสะดวก

**สิ่งที่ควรทำ**

- เพิ่มคำอธิบายสัญลักษณ์บนแผนที่
- ใช้สีที่แตกต่างกันอย่างชัดเจนสำหรับแต่ละสถานะ
- เพิ่มชื่อสถานที่หรือหมายเลขประจำจุด
- ปรับขนาดหมุดให้สามารถกดได้สะดวกบนโทรศัพท์มือถือ

## 2. เพิ่มรายละเอียดของสิ่งอำนวยความสะดวก

ผู้ใช้ต้องการทราบข้อมูลของแต่ละจุดมากขึ้น เพื่อประกอบการตัดสินใจในการใช้งาน

**สิ่งที่ควรเพิ่ม**

- ชื่อสิ่งอำนวยความสะดวก
- ตำแหน่งของสถานที่
- สถานะปัจจุบัน
- รายละเอียดปัญหาที่เกิดขึ้น
- วันที่แจ้งซ่อมและวันที่อัปเดตสถานะล่าสุด

## 3. ปรับปรุงระบบแจ้งซ่อม

เพิ่มความสะดวกในการแจ้งปัญหา เพื่อให้ผู้ใช้งานสามารถแจ้งซ่อมได้รวดเร็วและเข้าใจง่าย

**ประเภทปัญหาที่สามารถเลือกได้ เช่น**

- ห้องน้ำชำรุด
- ม้านั่งชำรุด
- ไฟส่องสว่างเสีย
- เครื่องออกกำลังกายชำรุด
- อุปกรณ์ภายในสวนเสียหาย
- พื้นที่ภายในสวนชำรุด

**สิ่งที่ควรเพิ่ม**

- ระบบเลือกประเภทปัญหา
- ระบบแนบรูปภาพประกอบ
- ระบบระบุตำแหน่งปัญหาบนแผนที่
- ช่องกรอกรายละเอียดเพิ่มเติม
- ข้อความยืนยันหลังจากแจ้งซ่อมสำเร็จ

## 4. เพิ่มระบบติดตามสถานะการแจ้งซ่อม

ผู้ใช้ต้องการทราบว่าปัญหาที่แจ้งไปได้รับการดำเนินการแล้วหรือยัง

**รูปแบบสถานะที่ควรเพิ่ม**

1. แจ้งปัญหา - ผู้ใช้งานส่งรายการแจ้งซ่อม
2. รับเรื่อง - เจ้าหน้าที่ได้รับข้อมูลแล้ว
3. กำลังดำเนินการ - เจ้าหน้าที่กำลังแก้ไขปัญหา
4. แก้ไขแล้ว - ปัญหาได้รับการแก้ไขเรียบร้อย

นอกจากนี้ควรเพิ่มเลขที่รายการแจ้งซ่อมและวันที่อัปเดตสถานะล่าสุด เพื่อให้ผู้ใช้ติดตามข้อมูลได้ง่ายขึ้น

## 5. เพิ่มระบบค้นหาและตัวกรอง

เพื่อช่วยให้ผู้ใช้งานค้นหาสิ่งอำนวยความสะดวกได้สะดวกขึ้น

**สิ่งที่ควรเพิ่ม**

- ค้นหาสถานที่จากชื่อ
- กรองประเภทสิ่งอำนวยความสะดวก
- กรองตามสถานะพร้อมใช้งานหรือกำลังซ่อมแซม
- แสดงจำนวนสิ่งอำนวยความสะดวกในแต่ละสถานะ

# 4. Next Mode(s) Based on User Feedback

จาก Feedback ที่ได้รับ ทีมควรกลับไปปรับปรุงในขั้นตอน Prototype โดยเน้นพัฒนาฟีเจอร์ที่เกี่ยวข้องกับการแจ้งซ่อม การแสดงข้อมูลบนแผนที่ และการติดตามสถานะให้มีความชัดเจนมากขึ้น โดยไม่จำเป็นต้องเริ่มกระบวนการใหม่ทั้งหมด

## Prototype Iteration

### 1. User Mode

ปรับปรุงประสบการณ์ของผู้ใช้งานทั่วไปให้สามารถ

- เข้าสู่ระบบได้สะดวก
- ดูแผนที่และตำแหน่งสิ่งอำนวยความสะดวก
- ตรวจสอบสถานะของแต่ละจุด
- กดหมุดเพื่อดูรายละเอียด
- แจ้งปัญหาหรือแจ้งซ่อม
- แนบรูปภาพและระบุตำแหน่งปัญหา
- ติดตามสถานะการแจ้งซ่อม

### 2. Staff Mode

เพิ่มระบบสำหรับเจ้าหน้าที่เพื่อจัดการรายการแจ้งซ่อม ได้แก่

- ดูรายการปัญหาที่ผู้ใช้งานแจ้งเข้ามา
- ดูรายละเอียดและตำแหน่งของปัญหา
- รับเรื่องและมอบหมายงาน
- เปลี่ยนสถานะการดำเนินงาน
- อัปโหลดรูปภาพหลังดำเนินการซ่อม
- ปิดรายการแจ้งซ่อมเมื่อแก้ไขเรียบร้อย

### 3. Admin / Management Mode

เพิ่มระบบสำหรับผู้ดูแลสวนเพื่อบริหารจัดการสิ่งอำนวยความสะดวก ได้แก่

- ดูจำนวนสิ่งอำนวยความสะดวกทั้งหมด
- ตรวจสอบจำนวนจุดที่พร้อมใช้งาน
- ตรวจสอบจำนวนจุดที่กำลังซ่อมแซม
- ดูประวัติการแจ้งซ่อม
- วิเคราะห์พื้นที่ที่เกิดปัญหาบ่อย
- ตรวจสอบประสิทธิภาพการดำเนินงานของเจ้าหน้าที่
- วางแผนการบำรุงรักษาสิ่งอำนวยความสะดวก

## การทดสอบรอบถัดไป (Usability Testing Round 2)

หลังจากปรับปรุง Prototype แล้ว ควรทดสอบอีกครั้งเพื่อประเมินว่าการเปลี่ยนแปลงช่วยแก้ไขปัญหาที่พบจากรอบแรกได้หรือไม่ โดยทดสอบประเด็นดังนี้

- ผู้ใช้สามารถค้นหาสิ่งอำนวยความสะดวกบนแผนที่ได้ง่ายขึ้นหรือไม่
- ผู้ใช้เข้าใจสัญลักษณ์และสถานะบนแผนที่หรือไม่
- ผู้ใช้สามารถแจ้งซ่อมได้สะดวกและรวดเร็วขึ้นหรือไม่
- ผู้ใช้สามารถติดตามสถานะการแจ้งซ่อมได้หรือไม่
- เจ้าหน้าที่สามารถรับเรื่องและจัดการรายการแจ้งซ่อมได้สะดวกหรือไม่
- ผู้ใช้มีความมั่นใจในการใช้งานระบบมากขึ้นหรือไม่
