# Prototype Testing: แอปตรวจสอบและแจ้งปัญหาในสวนสาธารณะ

## 1. วัตถุประสงค์การทดสอบ

ตรวจสอบว่าผู้ใช้สามารถเข้าใจและใช้งานฟีเจอร์หลักของ Prototype ได้จริง ได้แก่

- ระบบแจ้งปัญหาผ่าน QR Code
- ระบบแจ้งปัญหา เช่น ห้องน้ำสกปรก ม้านั่งชำรุด และน้ำไม่ไหล
- ระบบแสดงข้อมูลการทำความสะอาดและตรวจสอบห้องน้ำ
- ระบบวิเคราะห์ช่วงเวลาที่มีผู้ใช้งานหนาแน่น เพื่อช่วยจัดสรรเจ้าหน้าที่และทรัพยากร

รวมถึงเก็บ Feedback จากผู้ใช้งาน เพื่อนำไปวางแผนและปรับปรุง Prototype ในรอบถัดไป

---

## Task ที่ให้ผู้ทดสอบทำ

1. เปิดแอปครั้งแรก และลองดูว่าภายในสวนมีพื้นที่หรือบริการอะไรที่สามารถตรวจสอบได้บ้าง
2. ทดลองแจ้งปัญหา **“ห้องน้ำสกปรก”** ผ่าน QR Code
3. ทดลองแจ้งปัญหา **“ม้านั่งชำรุด”** พร้อมระบุตำแหน่งของปัญหา
4. เปิดหน้าข้อมูลห้องน้ำ แล้วตรวจสอบว่า **ทำความสะอาดล่าสุดเมื่อไหร่**
5. ตรวจสอบตารางการตรวจสอบ/ทำความสะอาดห้องน้ำครั้งถัดไป
6. ตรวจสอบสถานะปัญหาที่แจ้งไปว่าอยู่ในขั้นตอนไหน เช่น **รอดำเนินการ / กำลังแก้ไข / แก้ไขแล้ว**
7. ดูข้อมูลช่วงเวลาที่มีผู้ใช้งานหนาแน่น และบอกว่าคิดว่าควรเพิ่มทรัพยากรอะไรในช่วงเวลาดังกล่าว
8. สรุปให้ฟังว่าหน้าจอไหนเข้าใจง่าย/ยากที่สุด และเพราะอะไร

---

## คำถามหลังทดสอบ (Post-test Interview)

- ฟีเจอร์ไหนใช้งานง่ายที่สุด/ยากที่สุด เพราะอะไร?
- คุณเข้าใจไหมว่า QR Code ใช้สำหรับแจ้งปัญหาอะไรได้บ้าง?
- ข้อมูล “ทำความสะอาดล่าสุด” ทำให้คุณมั่นใจในการใช้พื้นที่มากขึ้นหรือไม่?
- สถานะการแจ้งปัญหาชัดเจนพอไหม?
- มีข้อมูลหรือฟีเจอร์อะไรที่คุณคาดว่าจะเห็น แต่ไม่มีในแอปนี้?
- หากพบปัญหาในสวนจริง คุณคิดว่าจะใช้แอปนี้แจ้งปัญหาหรือไม่ เพราะอะไร?
- ให้คะแนนความง่ายในการใช้งาน **1–5** พร้อมเหตุผล

# 3. What to Do Next from Test Feedback

## ประเด็นที่ต้องแก้ไข

### 1. เพิ่มความชัดเจนของระบบแจ้งปัญหา

ผู้ใช้บางคนไม่มั่นใจว่าเมื่อแจ้งปัญหาแล้ว ข้อมูลจะถูกส่งไปยังใคร

**สิ่งที่ควรทำ**
- ระบุผู้รับผิดชอบให้ชัดเจน
- เพิ่มข้อความยืนยันหลังแจ้งปัญหา
- แสดงเลขที่การแจ้งปัญหา
- เพิ่มสถานะการดำเนินงาน

---

### 2. เพิ่มระบบติดตามสถานะปัญหา

ผู้ใช้ต้องการทราบว่าปัญหาที่แจ้งได้รับการดำเนินการแล้วหรือยัง

**รูปแบบสถานะ**

`แจ้งปัญหา → รับเรื่อง → กำลังแก้ไข → แก้ไขแล้ว`

และควรเพิ่มเวลาโดยประมาณในการดำเนินการ หากสามารถคำนวณได้

---

### 3. ปรับปรุงข้อมูลการทำความสะอาด

ผู้ใช้ต้องการความมั่นใจว่าข้อมูลที่เห็นเป็นข้อมูลปัจจุบัน

**สิ่งที่ควรเพิ่ม**

- ทำความสะอาดล่าสุด: 10:30 น.
- ตรวจสอบล่าสุด: 11:00 น.
- รอบตรวจครั้งถัดไป: 13:00 น.
- อัปเดตข้อมูลล่าสุด: 11:05 น.

---

### 4. ปรับปรุงการแสดงข้อมูลช่วง Peak Hour

ผู้ใช้ยังไม่เข้าใจว่าทำไมต้องเพิ่มเจ้าหน้าที่หรือทรัพยากรในบางช่วงเวลา

**สิ่งที่ควรทำ**
- เพิ่มกราฟจำนวนผู้ใช้งาน
- แสดงช่วงเวลาที่มีผู้ใช้งานหนาแน่น
- แสดงจำนวนเจ้าหน้าที่ที่เหมาะสม
- แสดงทรัพยากรที่ควรเพิ่ม เช่น ถังขยะ ห้องน้ำ หรือจุดบริการน้ำ

---

### 5. เพิ่มความสะดวกในการแจ้งปัญหา

ลดขั้นตอนที่ไม่จำเป็น เพื่อให้ผู้ใช้สามารถแจ้งปัญหาได้อย่างรวดเร็ว

**ประเภทปัญหาที่สามารถเลือกได้ เช่น**

- ห้องน้ำสกปรก
- น้ำไม่ไหล
- ม้านั่งชำรุด
- ไฟเสีย
- พื้นที่ชำรุด
- ถังขยะเต็ม

สามารถเพิ่มการ **แนบรูปภาพ** และ **ระบุตำแหน่ง** เพื่อช่วยให้เจ้าหน้าที่แก้ไขปัญหาได้ง่ายขึ้น

---

# 4. Next Mode(s) Based on User Feedback

จาก Feedback ที่ได้ ทีมควรกลับไปที่ขั้น **Prototype** เพื่อปรับปรุงรายละเอียดของระบบ โดยไม่จำเป็นต้องเริ่มกระบวนการใหม่ทั้งหมด เนื่องจากปัญหาที่พบส่วนใหญ่เป็นปัญหาด้าน **UI/UX และ Information Design**

## Prototype Iteration

### 1. User Mode

ปรับปรุงประสบการณ์ของผู้ใช้ให้สามารถ

- สแกน QR Code
- เลือกประเภทปัญหา
- แนบรูปภาพ
- ระบุตำแหน่ง
- ส่งปัญหา
- ติดตามสถานะ

ได้ง่ายและรวดเร็วขึ้น

---

### 2. Staff Mode

เพิ่มระบบสำหรับเจ้าหน้าที่เพื่อ

- ดูรายการปัญหาที่ได้รับแจ้ง
- ดูตำแหน่งปัญหา
- รับเรื่อง
- เปลี่ยนสถานะการดำเนินงาน
- อัปโหลดรูปหลังแก้ไข
- ปิดรายการปัญหา

---

### 3. Admin / Management Mode

เพิ่มระบบสำหรับผู้ดูแลสวนเพื่อ

- ดูจำนวนปัญหาในแต่ละพื้นที่
- ดูช่วงเวลาที่มีปัญหามากที่สุด
- วิเคราะห์ช่วง Peak Hour
- ดูจำนวนผู้ใช้งาน
- จัดตารางเจ้าหน้าที่
- จัดสรรทรัพยากร เช่น ถังขยะ ห้องน้ำ และจุดบริการน้ำ

---

## การทดสอบรอบถัดไป

หลังจากปรับ Prototype แล้ว ควรทำ **Usability Testing รอบที่ 2** เพื่อทดสอบว่า

1. ผู้ใช้สามารถแจ้งปัญหาได้เร็วขึ้นหรือไม่
2. ผู้ใช้เข้าใจสถานะการแจ้งปัญหาหรือไม่
3. ผู้ใช้เข้าใจข้อมูลการทำความสะอาดหรือไม่
4. ผู้ใช้เข้าใจเหตุผลของการจัดสรรทรัพยากรตามช่วงเวลาได้หรือไม่
5. ผู้ใช้รู้สึกมั่นใจในการใช้งานระบบมากขึ้นหรือไม่
